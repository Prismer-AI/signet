# Account Outreach Playbook

Date: 2026-04-23
Scope: first 20 target accounts for founder-led outbound

## Goal

Get 3-5 serious design-partner conversations around one narrow wedge:

**trusted execution for MCP and agent workflows**

Do not pitch "AI security platform." Pitch one protected workflow.

## Ideal Roles

- Champion: Head of AI Platform, Internal AI, Dev Productivity, AI Engineering
- Control owner: Security Engineering, Security Architecture, IAM, GRC
- Workflow owner: IT Ops, RevOps, Internal Tools, Knowledge Systems
- Buyer: CIO, CISO, VP Engineering, VP Platform

## Outreach Sequence

1. Start with one short email.
2. Follow with one LinkedIn message 2-3 days later.
3. If engaged, offer a 20-minute technical walkthrough.
4. If no response, send one tighter workflow-specific follow-up.

## Cold Email Template

Subject: `Trusted execution for your MCP / agent workflows`

```text
Saw that [Company] is already pushing into [MCP / agents / governed AI workflows].

The gap we keep seeing is that logs show activity, but they do not prove that a tool call was trusted at the execution boundary.

Signet adds signed requests, trusted execution receipts, and offline-verifiable audit trails for agent actions without replacing your existing stack.

For [Company], I would focus the demo on [one concrete workflow].

If useful, I can show a 20-minute walkthrough next week.
```

## LinkedIn DM Template

```text
Saw your recent work around [agents / MCP / governance]. We are building a narrow layer for one problem: proving that an agent-triggered action was trusted when it crossed the execution boundary.

Not another dashboard. More like signed requests + verifiable receipts for one workflow. Happy to send a short demo if relevant.
```

## Follow-Up Template

```text
Quick follow-up on this. I am not suggesting a platform replacement.

The idea is much narrower:
- sign one agent request path
- verify before execution
- export a receipt trail that can be checked later

If you are already operating [MCP / internal agents / approval workflows], this is usually easiest to evaluate on one protected workflow.
```

## Discovery Questions

- Which workflows already let agents take action, not just read data?
- Where do approvals, permissions, or exceptions break down today?
- If an incident happened, what evidence would your team rely on?
- Is the current audit trail provider-owned, customer-owned, or both?
- Which workflow would be safest to pilot in 2 weeks?

## Qualification

Prioritize accounts that already have all three:

- production or near-production agent workflows
- internal tools or MCP exposure
- a security, compliance, or governance owner in the loop
